# Аккаунты и вход

Статус: **код сервера готов в черновике** (`server/app/routers/auth.py`, тесты в `tests/test_api.py`).
Экраны входа и регистрации доступны в приложении через «Настройки → Аккаунт» и на первом запуске; клиент `js/api.js` подключён.
Без настроенного адреса API формы не отправляют запросы. Регистрация дополнительно требует URL опубликованной политики.
Синхронизация данных группы, подтверждение почты и отправка писем сброса пароля пока не подключены.

## Кто входит

| Роль | Кто | Что может |
|---|---|---|
| `head` | староста | всё: данные группы, почта, приглашения, удаление группы |
| `deputy` | зам старосты | данные группы (отметки, сдачи, дела), «Почта»; не подключает почту и не приглашает |
| `viewer` | (позже) куратор, второй зам | только смотреть |

Один аккаунт может быть в нескольких группах (например, староста потока). Студенты аккаунтов пока не имеют.

## Вход по логину

- **Логин**: 3–32 символа, латиница, цифры, `.`, `-`, `_`, хранится в нижнем регистре (`Starosta1` = `starosta1`).
- Войти можно **логином или почтой** — одно поле «Логин или почта».
- **Пароль**: от 8 символов, буквы и цифры, не содержит логин. Хранится только хеш Argon2id.
- **Почта** обязательна при регистрации — только для сброса пароля и важных уведомлений, не для рассылок.
- Ответ на неверный логин и на неверный пароль одинаковый — «Неверный логин или пароль».
- Защита от подбора: 10 попыток за 15 минут на логин, 50 — на IP (сейчас в памяти, на сервере — Redis).

## Как хранится вход

1. После входа сервер создаёт случайный токен (32 байта), в базу кладёт **только его SHA-256**.
2. Токен уходит в cookie `starosta_session`: `HttpOnly` (скрипты страницы его не видят), `Secure` (только HTTPS),
   `SameSite=Lax`, срок 30 дней.
3. Изменяющие запросы (POST/PUT/DELETE) принимаются только с заголовком `X-Starosta: 1`. Чужой сайт не может
   его поставить: CORS разрешает запросы с cookie только с адреса приложения (`STAROSTA_APP_ORIGIN`).
4. Выход удаляет сессию на сервере. Смена пароля через сброс — выход на всех устройствах.

Почему не JWT в localStorage: любой внедрённый скрипт его прочитает, а отозвать его до истечения срока нельзя.

## Сброс пароля

`POST /auth/password/forgot {email}` → письмо со ссылкой `…/#reset/<токен>` (живёт 1 час, одноразовая) →
экран «Новый пароль» → `POST /auth/password/reset`. Ответ на «forgot» всегда одинаковый — не выдаём, есть ли такая почта.
**Нужно для запуска:** отправка писем (SMTP-сервис в РФ: Unisender Go, Yandex Cloud Postbox или почта домена в Яндекс 360).
Пока ссылка пишется в журнал сервера.

## Приглашение зама

Староста: «Настройки → Доступ → Пригласить зама» → код `A1B2-C3D4-E5F6` (3 дня, одноразовый) → передаёт заму.
Зам: регистрируется → «Присоединиться к группе» → вводит код. Код в базе — только хешем.

## Связь с тем, что уже есть в приложении

- **Без аккаунта** — как сейчас. Кнопка «Войти» — в настройках и на стартовом экране, не навязчиво.
- **План следующего этапа — перенос данных**: галочка «Перенести данные с этого устройства» → `POST /groups {title, data}`.
- Пока перенос не реализован, экран аккаунта прямо сообщает, что локальные данные остаются только в браузере.
- **PIN-код** (уже есть) остаётся: он защищает приложение на устройстве, аккаунт — данные на сервере.
- **Выход** спрашивает: «Оставить копию данных на этом устройстве?» (по умолчанию — нет, если устройство чужое).

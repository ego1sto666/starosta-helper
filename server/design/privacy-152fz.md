# Персональные данные и 152-ФЗ — что нужно до запуска для других старост

> Это рабочий список для разработки, **не юридическая консультация**. Перед публичным запуском показать юристу
> (в вузе есть юридическая клиника или юрфак) — особенно пункты 1–3.

Пока приложение работает без сервера, данные лежат только у старосты на устройстве — мы их не обрабатываем.
**Как только появляется сервер, мы становимся оператором персональных данных** (или обрабатываем их по поручению
старосты): ФИО, телефоны, почты, дни рождения студентов, посещаемость, оценки, письма преподавателей.

## Обязательное

1. **Локализация (ст. 18 ч. 5).** Базы с персональными данными граждан РФ — на серверах в России.
   → VPS и хранилище файлов только у российских провайдеров (Timeweb Cloud, Selectel, Yandex Cloud).
   Никаких зарубежных сервисов для писем, файлов, аналитики, логов с персональными данными.
2. **Уведомление Роскомнадзора (ст. 22)** о начале обработки — до запуска. Подаётся онлайн на pd.rkn.gov.ru.
   Оператор — тот, кто запускает сервис (физлицо, самозанятый или ИП — уточнить с юристом).
3. **Политика обработки персональных данных** — опубликована на сайте: какие данные, зачем, сколько храним,
   как удалить, контакты. **Согласие** при регистрации — отдельная галочка (уже заложено: `consent` в `/auth/register`).
4. **Данные студентов вносит староста.** В политике и при регистрации: староста подтверждает, что вносит данные
   одногруппников для организации учёбы группы и сообщил им об этом. Телефон, почта, день рождения — необязательные поля.
5. **Защита (ст. 19, ПП № 1119).** HTTPS везде, пароли — Argon2id, секреты почты зашифрованы, доступ к серверу по
   SSH-ключу, резервные копии базы — зашифрованные и тоже в РФ, журнал действий (`audit_log`).
6. **Утечки.** С 30.05.2025 штрафы за утечки выросли многократно; об утечке нужно сообщить в РКН в течение 24 часов.
   → Минимум данных, шифрование, план «что делать при утечке» (кому писать, как сменить ключи).

## Как это заложено в коде

| Мера | Где |
|---|---|
| Письма не от преподавателей группы не сохраняются вообще | `mail/service.py → ingest` |
| Письма и вложения хранятся 60 дней, потом удаляются | `MailMessage.expires_at`, `worker.cleanup` |
| Пароль от почты не нужен (пересылка); пароль приложения — зашифрован, наружу не отдаётся | `mail/inbound.py`, `security.encrypt_secret`, `routers/mail.py → source_out` |
| Пароли пользователей — только хеш Argon2id | `security.hash_password` |
| Токены входа и коды приглашений — только хеши | `AuthSession.token_hash`, `Invite.code_hash` |
| Согласие при регистрации обязательно, время согласия хранится | `RegisterIn.consent`, `User.consent_at` |
| Журнал важных действий | `AuditLog` |
| Удаление группы удаляет всё каскадом | `ondelete="CASCADE"` в `models.py` |

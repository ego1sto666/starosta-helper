# Серверная архитектура «Помощника старосты»

Общая информационная и техническая архитектура проекта: [`../../ARCHITECTURE.md`](../../ARCHITECTURE.md). Этот файл фиксирует серверные границы и их текущее состояние.

## Сейчас

- `server/app/main.py` собирает FastAPI, CORS и общую проверку изменяющих запросов.
- `server/app/routers/auth.py` отвечает за регистрацию и сессии; `groups.py` — за группы, доступ и синхронизацию; `mail.py` — за источники писем и предложения.
- `server/app/deps.py` проверяет сессию и членство в группе на каждом защищённом маршруте.
- `server/app/models.py` описывает аккаунты, членство, ревизию JSON-данных группы и почтовые сущности. Локально используется SQLite; `docker-compose.yml` предусматривает PostgreSQL.
- `server/app/mail/` разбирает, принимает и проверяет письма; `server/app/worker.py` выполняет периодическую работу.
- `js/api.js` подключён к приложению и синхронизирует группу при запуске через `Открыть с аккаунтом.bat`.

## Границы

1. Браузер хранит офлайн-копию и показывает интерфейс. Пароли учётной записи и почтовые секреты остаются на сервере.
2. API проверяет права на **конкретную группу** до чтения и изменения её данных или писем. Староста, заместитель и наблюдатель имеют разные права.
3. Данные группы хранятся одним JSON с `rev`; сервер возвращает `409` при устаревшей ревизии, после чего клиент сливает изменения. Подробности: [`sync.md`](sync.md).
4. Письма принимаются в контексте группы и превращаются в предложения, которые подтверждает староста. Подробности: [`mail.md`](mail.md).
5. Один API и одна база достаточны для пилота. Отделять сервисы и добавлять балансировщик следует после замеров нагрузки.

## До публикации

Нужны миграции БД, проверенные резервные копии, домен и HTTPS, доставка писем восстановления, проверка реального IMAP, обработка вложений и подготовка к работе с персональными данными. Точные задачи — в [`../../ROADMAP.md`](../../ROADMAP.md) и [`privacy-152fz.md`](privacy-152fz.md). Текущий Docker Compose — подготовка к развёртыванию, а не свидетельство готового публичного сервиса.

# Синхронизация данных между устройствами

Статус: локальный сервер подключён к приложению. Данные сохраняются по ключу аккаунта и группы;
слияние проверено в `tests/sync-merge.html`, сценарий группы и почты — в `tests/cloud.html`.

## Этап 1 — весь документ целиком (делаем первым)

Данные группы — тот же JSON, что сейчас в `localStorage` (`starosta.data`): студенты, преподаватели, пары,
журнал, переносы, дела, сдачи, сборы, документы, опросы, шаблоны, оценки, настройки.

- На сервере: `group_data {group_id, rev, data}`. `rev` растёт на 1 при каждом сохранении.
- Приложение помнит `rev` и «основу» — версию данных, с которой начало изменения.
- Изменили что-то → через 3 секунды тишины `PUT {rev, data}`.
  - `rev` совпал → сохранено, новый `rev`.
  - Сервер ответил **409** (зам успел сохранить раньше) → в ответе свежие данные → **трёхстороннее слияние**
    (основа, моё, серверное) → повторить (до 3 раз).
- Открыли приложение / вернулись на вкладку → `GET` и слияние с локальными несохранёнными изменениями.
- Нет сети → данные остаются в браузере, плашка «Нет сети — сохраним, когда появится».

### Правила слияния (`mergeData`)

Для каждого поля записи с `id` (студент, пара, дело, сдача…) и для каждого ключа словарей
(`attendance["2026-11-06|id пары"]`, `overrides`, `settings`):

| Основа → моё / серверное | Итог |
|---|---|
| изменил только я | моё |
| изменил только другой | серверное |
| изменили оба | моё (кто сейчас за экраном) |
| я удалил, другой не трогал | удалено |
| я удалил, другой изменил | остаётся изменённое (правка важнее удаления) |
| добавили оба разное | оба |

Журнал сливается по паре и по студенту. Отметки разных студентов сохраняются, даже если их поставили
одновременно на одной паре. При конфликте двух отметок одного студента действует правило для одного поля.

### Ограничения этапа 1

- Размер — до 5 МБ (как и в браузере). Фото справок и аватары хранятся в данных: аватары маленькие (~8 КБ),
  **фото справок** на этапе 1 не синхронизируются (они в IndexedDB) — переедут в хранилище файлов на шаге 6.
- Отправляется весь документ — для одной группы это десятки–сотни КБ, приемлемо.

## Этап 2 — изменения по записям (когда понадобится)

Когда у группы будет 3+ активных устройства или появятся ответы студентов — переход на журнал изменений:
`POST /groups/{id}/ops [{op: "set", path: "students/abc/name", value, ts}]`, сервер раздаёт изменения другим
устройствам через Server-Sent Events. Формат данных при этом не меняется.

## Подключение в приложении (шаг 4)

```js
const sync = StarostaAPI.createSync({ groupId, getData: () => DB, setData: d => { DB = normalize(d); persist(); render(true); },
                                       onState: s => showSyncBadge(s) });
await sync.pull();               // при открытии
// в persist(): sync.changed();  // после каждого сохранения
```

# Сервер «Помощника старосты»

**Статус: локальная рабочая версия.** Запуск `server/dev_local.py` подключает API к приложению.
Регистрация, группы, синхронизация и чтение почты через IMAP работают локально. Публичный сервер не развёрнут;
остающиеся шаги описаны в `../ROADMAP.md`.

Что уже есть и проверено тестами:
- аккаунты: регистрация, вход по логину или почте, выход, защита от подбора; сброс пароля до настройки исходящей почты недоступен;
- группы: создание с переносом данных с устройства, синхронизация `data.json` с версиями и конфликтами,
  приглашение зама по коду;
- почта: адрес пересылки у каждой группы, подключение ящика по IMAP (пароль шифруется), фильтр
  «только от преподавателей группы», разбор писем (даты, тип, предмет), экран «Почта» (принять/отклонить).

## Запуск на своём компьютере

Нужен Python 3.11+. Из папки `server`:

```
python -m venv .venv
.venv\Scripts\activate            (Windows; на macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env            (и поменять STAROSTA_SECRET_KEY)
uvicorn app.main:app --reload --port 8000
```

Документация API с кнопкой «Попробовать»: http://127.0.0.1:8000/docs

Для локального приложения запустите из корня проекта `.\server\.venv\Scripts\python.exe .\server\dev_local.py`
(на этом компьютере есть ярлык `Открыть с аккаунтом.bat`): скрипт создаст
`server/.env` со случайным ключом, запустит API, проверку IMAP и сайт. Пароли приложений почты
проверяются до сохранения и хранятся в базе зашифрованными. Для Яндекса и Mail включите IMAP и создайте
отдельный пароль приложения в настройках почты; для Gmail нужен поддерживаемый аккаунтом пароль приложения.
Письма импортируются только с адресов преподавателей выбранной группы.

## Подключение интеграций на тестовой группе

Сначала откройте локальную версию с аккаунтом и перенесите группу на сервер. Настройки берите из `.env.example`,
секреты сохраняйте только в `server/.env` и `server/secrets/`. После правок перезапустите API и нужный фоновый процесс.

1. **Почта группы.** Добавьте адреса преподавателей в их карточки и дождитесь синхронизации. Самый короткий путь —
   завести общий ящик у почтового провайдера, сообщить его преподавателям и подключить в «Почта → Подключённые ящики»
   через IMAP и пароль приложения. Существующая почта преподавателей попадёт в приложение, если преподаватели
   добавят этот ящик в получатели или владелец исходного ящика настроит переадресацию. Проверка: одно письмо с адреса
   преподавателя, одно с чужого адреса и повтор первого. Во входящих должно остаться одно письмо. Текст доступен в
   приложении; содержимое вложений пока читается в исходном ящике.
2. **Адрес на своём домене.** Если нужен адрес, который показывает приложение, направьте MX на доверенный почтовый
   шлюз. Шлюз проверяет отправителя по правилам провайдера и передаёт исходное письмо, сохраняя исходный `From` и
   `Message-ID`. Отправляйте `POST /api/integrations/mail/<код-получателя>` по HTTPS с телом `message/rfc822` и
   заголовком `X-Starosta-Mail-Token`; код берётся из SMTP-получателя, до знака `@`. Значение токена (от 32 символов)
   должно совпадать с `STAROSTA_MAIL_RELAY_TOKEN`. Ограничьте отправителей на стороне шлюза, а не только по заголовку
   `From` в письме. Ответ 204 означает, что запрос обработан, в том числе для повтора и письма вне списка.
   Подключение конкретного почтового шлюза и его DNS выполняется отдельно. Профиль `trusted-smtp` оставлен для
   закрытой схемы со своим доверенным шлюзом; SMTP-порт в Compose не публикуется.
3. **Пуши.** Из папки `server` выполните `python tools/push_keys.py secrets/vapid.pem`. Скопируйте выведенный
   публичный ключ в `STAROSTA_PUSH_PUBLIC_KEY`. Укажите `STAROSTA_PUSH_PRIVATE_KEY_FILE=secrets/vapid.pem` локально
   или `/run/starosta/vapid.pem` в Compose, а в `STAROSTA_PUSH_SUBJECT` — контакт администратора вида
   `mailto:admin@example.org`. В аккаунте откройте «Настройки → Приложение → Пуш-уведомления», включите подписку,
   отправьте проверку и закройте вкладку. При нажатии на уведомление откроются настройки. Автоматическая доставка
   напоминаний и новых писем остаётся следующим шагом; существующие напоминания открытой вкладки работают как раньше.
4. **Telegram.** Зарегистрируйте бота через BotFather и добавьте в один тестовый чат группы. Чтобы видеть обычные
   сообщения с опросами, отключите Privacy Mode и при необходимости добавьте бота заново. Укажите токен, отрицательный
   ID чата и ID облачной группы (поле `id` в авторизованном ответе `GET /groups`). Запустите один процесс
   `python -m app.telegram` либо `docker compose --profile telegram up -d telegram`. Для этого бота не должен быть
   активен вебхук. Создайте новый опрос, проголосуйте и завершите его, затем откройте «Опросы → Опросы из Telegram».
   Это снимки вопроса, вариантов и общих итогов. Для чужих опросов не гарантируются обновления каждого голоса.
   История чата и персональные ответы ботом не запрашиваются.

## Тесты

```
python -m unittest discover -s tests -t . -v
```

- `tests/test_parse.py` — разбор писем; работает даже без установки библиотек.
- `tests/test_api.py` — весь путь: регистрация → группа → синхронизация и конфликт → письмо преподавателя и
  чужое письмо → «Почта» → приглашение зама. База — временный файл, настоящие данные не трогаются.

После изменения таблиц или API обновить документы: `python tools/export_contract.py`.

## На сервере

`docker-compose.yml`: PostgreSQL, API, `worker` (IMAP и очистка), Caddy (HTTPS), отдельные профили для Telegram и
закрытого SMTP. Для публикации нужны VPS, домен, `.env`, `DB_PASSWORD` и конфигурация сайта с
`STAROSTA_API=/api` и ссылкой на политику обработки данных. MX требуется только для своего почтового адреса.
Подробно — шаг 2 в `../ROADMAP.md`.
